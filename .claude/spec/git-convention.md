# Git Convention

## 커밋 메시지

형식: `{type}: 커밋 내용(#{이슈번호})`

| type | 용도 |
|---|---|
| feat | 새로운 기능 |
| fix | 버그 수정 |
| hotfix | 긴급 수정 |
| docs | 문서 변경 |
| test | 테스트 추가/수정 |
| refactor | 리팩토링 |
| chore | 빌드, 설정 등 기타 |

예시: `feat: 이상 명령 탐지 규칙 추가(#12)`

## 제목 규칙

- 40자 이내, 명사형으로 끊어 쓴다
- 대상을 나열하지 말고 "무엇을 해결했는지"를 남긴다
- 클래스명 나열과 괄호 중첩을 쓰지 않는다

## 표기 규칙

- 가운데점(`·`) 대신 콤마(`,`), 긴 대시(`—`) 대신 짧은 대시(`-`)를 쓴다

## 브랜치 전략

- `main` → `dev` → 각자 개발 브랜치
- main/dev에 직접 커밋하지 마라
- 개발 브랜치 네이밍: `{type}/{이슈번호}-{간단한설명}` (예: `feat/12-detect-rule`)
